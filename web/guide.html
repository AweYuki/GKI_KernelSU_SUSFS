Before You StartRead this first

Note

To use GitHub Actions you must work inside your own repository, either a personal repo or your fork of this project. Make sure the top-left corner shows your username, otherwise you will not be able to run workflows.

This page covers only two things: how to fork this repository, and how to build with GitHub Actions workflows.

01

Fork the RepositoryCreate your own copy

  1. Sign in to GitHub.
  2. Open the upstream repository: AweYuki/GKI_KernelSU_SUSFS
  3. Click Fork in the top-right corner and create your own copy.
  4. After forking, find your fork anytime from the sidebar in the top-left corner.
02

Enable GitHub ActionsAllow workflows to run

  1. Open your forked repository.
  2. Click the Actions tab at the top.
  3. If GitHub asks you to enable workflows, follow the on-screen instructions.
03

Choose and Run a WorkflowPick a version and start the build

  1. On the Actions page, select Custom Android Kernel Build.
  2. The workflow inputs decide which GKI kernel version will be built.
  3. Find these values on the version page: click a release to see its build parameters.
  4. Fill in the values and click Run workflow to start the build.
Tip

In short: the version page tells you what to enter, the workflow builds it automatically.

04

Download the ArtifactsGrab the kernel files

After the build finishes, open that workflow run’s detail page and download the output files from the Artifacts section at the bottom.

05

Sync Fork with UpstreamKeep your fork current

When the upstream repository is updated, click Sync fork on your fork’s page to pull the latest code and avoid build failures.

Warning

Do not click the Compare button next to it. That is not the sync feature.
